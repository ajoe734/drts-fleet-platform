### 3.5 Asia/Taipei 日期／金額格式化與 unknown vs 零

來源：`lib/format.ts`。

- 日期時間 `displayDateTime`：`Intl.DateTimeFormat`（zh→`zh-TW`、en→`en-US`），`timeZone: "Asia/Taipei"`、24 小時制、到秒。驗收方式：挑一筆已知 UTC 時間戳（例如 API 回傳 `…T16:30:00Z`）確認畫面顯示為台北時間次日 `00:30:00`，zh/en 兩者對應同一時刻，只是格式不同。
- 金額 `displayMinor`：以 `Intl.NumberFormat`（`zh-TW`/`en-US`）格式化 **minor 單位原值**後接幣別代碼（如 `1,250 TWD`）；不做 /100 換算、不加貨幣符號。請記錄 TWD 的實際顯示是否符合 parent 原需求；若不符，記錄為觀察，不在此改碼。
- 百分比 `displayPercent`：`rate*100` 取 2 位小數＋`%`。
- **unknown vs 零（關鍵）**：
  - `null`／`undefined`／非有限數字／空字串 → zh `未提供`／en `Not provided`，**絕不能顯示 0**。
  - 數值 `0` → 必須顯示 `0`（金額 `0 TWD`、`0.00%`、`distanceMeters` `0`），**絕不能顯示未提供**。
  - 要找的真實樣本：trip-records 的 `collectedFareMinor`/`tollMinor`/`route.distanceMeters`；operations 的 `onTimeTripCount`/`lateTripCount`/`noShowTripCount`/`punctualityUnknownTripCount`/`averageDispatchableVehicleCount`/`snapshotCoverageRate`；complaints 的 `lowRatingAuto`/`manual`。
  - 注意：operations 的 `demandRequestCount`、`actualDispatchCount`、`completedTripCount`、`cancelledOrderCount`、`complaintCount` 與 daily-dispatch 的 `redispatchCount`/`complaintCount`、complaints 的 `complaintCount` 是**直接輸出原值**（契約上為非 null 數字），不會顯示未提供——此為現行設計，記錄即可。
- 觀察項（請在 hosted 上確認並記錄，不改碼）：`/reports/daily-dispatch` 預設日期使用 `new Date().toISOString().slice(0,10)`（UTC 日期）。在 Asia/Taipei 00:00–07:59 之間開啟時，預設會是台北的「前一天」。
