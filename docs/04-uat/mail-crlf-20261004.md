## Observed failure and precise reproduction

Authorized hosted mail run [37195290171](https://github.com/ajoe734/drts-fleet-platform/actions/runs/37195290171)
against the base SHA produced real SMTP acceptance and a successful localized
`\\All` mailbox observation: exact Message-ID, matching content, read-only IMAP.
It then failed at `invitation_acceptance_failed` after a replacement invitation
was sent. Session teardown succeeded. The broad stage alone does not prove which
acceptance substep failed; it does NOT establish the complete invitation flow.
Raw redacted run artifacts are retained under the operator-local follow-through
evidence directory. No mailbox content, addresses or invitation tokens are in
this document.

Source inspection found a concrete parser defect. The production
`message_body()` preserves CRLF from SMTP MIME. Anchored regexes in
`invitation_from_body()` require the token/expiry to meet `$`, which rejects the
unconsumed CR before LF. Previous tests passed LF-only strings directly to the
parser, bypassing real MIME serialization.

The new tests serialize `EmailMessage(policy=policy.SMTP)` and call the real
`message_body`, `invitation_from_body` and `accept_invitation`. With the unchanged
base production file, the mailbox suite ran 30 tests and failed (1 failure,
4 subtest errors), all new positive SMTP cases reporting `Missing unique
invitation code`. The same input with LF-only line endings parses successfully.
No sockets, IMAP login or product runtime were used for this reproduction.

## Repair and retained boundaries

Normalize CRLF to LF only in the parser's local copy, before the existing
anchored matches. Do not normalize the original decoded body used for evidence
hashes. No whitespace folding, token format relaxation, default expiry, clock
fast-forward, link following or acceptance bypass.
