## 1. Executive Summary

This task remediates the two authoritative enterprise booking journey defects (`C014-C017-F1` and `C014-C015-F2`) identified in the audit of `apps/enterprise-dispatch-web` while preserving existing positive-credit boundaries (`C013`, `C016`, `C018`, and `C120`), and resolves the R1 commit-trailer subject gate finding (`EBAJ-R1-CI-01`):

1. **`C014-C017-F1` (`enterprise_signed_session_transport_and_tenant_scope`)**:
   - **Before (`ee731bba06354c219faed83a78db002e7a33144e`)**:
     - `apps/enterprise-dispatch-web/lib/api-client.ts` (`createEnterpriseDispatchTenantClient`) injected bootstrap identity headers (`x-realm: "tenant"`, `x-actor-type: "tenant_admin"`, `x-actor-id: "enterprise-dispatch-web"`) on every request and did not forward the verified `drts_tenant_session` bearer token or Cloud Run service-hop headers on SSR calls (`app/page.tsx`, `app/trip/page.tsx`).
     - `apps/enterprise-dispatch-web/app/control-plane-proxy/[...path]/route.ts` only checked `drts_tenant_session` for `GET /v1/tenant/bookings*`, leaving `POST /v1/tenant/bookings`, `PUT /v1/tenant/bookings/:id`, `PATCH /v1/tenant/bookings/:id`, and `POST /v1/tenant/bookings/:id/cancel` unverified at the proxy boundary and injecting configured bootstrap headers (`x-realm: "tenant"`, `x-actor-type: "tenant_admin"`, `x-actor-id`, `x-tenant-id`) upstream. In strict production/staging environments (`BootstrapAuthGuard`), any request carrying bootstrap headers is rejected with `401 AUTH_BOOTSTRAP_HEADERS_FORBIDDEN`.
     - `apps/enterprise-dispatch-web/app/bookings/review/booking-submit-button.tsx` defaulted `x-tenant-id` to the static fixture `enterpriseTenant.id` (`10000000-0000-0000-0000-000000000201`) instead of the verified session's `tenantId`.
   - **After**:
     - `apps/enterprise-dispatch-web/lib/enterprise-session.server.ts` extracts verified `scopes` (requiring `tenant:read`), `actorId`, and Cloud Run `upstreamHeaders` (`x-serverless-authorization`, `x-drts-google-id-token`) from `verifyEnterpriseTenantSession`.
     - `apps/enterprise-dispatch-web/app/control-plane-proxy/[...path]/route.ts` enforces `verifyEnterpriseTenantSession` on **all** `/v1/tenant/bookings*` and `/api/tenant/bookings*` operations (`GET`, `POST`, `PUT`, `PATCH`, and `/cancel`), enforces `tenant:read` for reads and `tenant:write` for mutations (`403 AUTH_SCOPE_DENIED`), rejects `x-tenant-id` mismatches against `verified.session.tenantId` (`403 TENANT_SCOPE_MISMATCH`), strips all bootstrap/spoofed headers (`x-realm`, `x-actor-type`, `x-actor-id`, `x-roles`, `x-role-families`, `x-scopes`, `x-auth-mode`, `x-partner-*`, `x-drts-authorization`, `x-drts-internal-key`, `x-drts-google-id-token`, `x-serverless-authorization`), and attaches `Authorization: Bearer ${verified.session.accessToken}` + `x-tenant-id: ${verified.session.tenantId}` + Cloud Run `upstreamHeaders`.
     - `apps/enterprise-dispatch-web/lib/api-client.ts` provides `createEnterpriseDispatchSessionClient(session, baseUrl)` and updates `getEnterpriseDispatchTenantClient(tenantOrSession)` so SSR callers (`app/page.tsx`, `app/trip/page.tsx`, `app/bookings/submitted/page.tsx`) receive an uncached request-scoped client carrying `Authorization: Bearer` + `x-tenant-id` + `upstreamHeaders` with zero bootstrap headers, while browser callers (`/control-plane-proxy`) send only `x-tenant-id` (and same-origin `drts_tenant_session` cookie) with zero bootstrap headers and without exposing `accessToken` in client props or global caches.
     - `apps/enterprise-dispatch-web/app/bookings/review/page.tsx` verifies `drts_tenant_session` on the server and passes `tenantId={verifiedTenantId}` (never `accessToken`) into `BookingSubmitButton`, which no longer imports `enterpriseTenant` from `lib/enterprise-fixtures`.
