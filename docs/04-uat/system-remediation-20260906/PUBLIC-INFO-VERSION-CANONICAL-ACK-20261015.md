Their existing completion/error UI remains the consumer of the corrected API contract. No SDK or page Source rewrite was necessary.

`PlatformAdminController.createPublicInfoVersion`, `publishPublicInfoVersion` and `deleteDraftPublicInfoVersion` now await the actual Service command before creating a success envelope. Publish/delete still obtain the actor from the existing verified identity; an actor supplied in the publish body does not replace it. Existing guards and routes remain unchanged.

The Service stages public-info changes against an authoritative repository snapshot. `PlatformAdminRepository.mutatePublicInfoVersions` reuses the existing table and `withTransaction` wrapper. A public-info table lock serializes this version/history lifecycle, including its initial-publication case. It reads canonical records, executes the staged upserts/deletes with row acknowledgements, reads the same version back inside the transaction, and returns only after the existing wrapper's COMMIT succeeds. Delete returns the acknowledged deleted before-image. Any write/readback/COMMIT rejection is rethrown by the transaction wrapper; the Service does not publish staged cache or a success audit on rejection.

For publication, old-version retirement and new-version publication are staged together and executed sequentially within the transaction. A controlled failure of the second write rolls the first back. A later legitimate retry succeeds; publishing the already published version still conflicts. Authoritative same-version readback supplies the returned record and cache snapshot.

The documented no-repository mode still applies staged local changes and returns the same fields asynchronously. It makes no durable-storage claim. Title, phone, complaint phone, call-rate text, fare text, payment method, effective dates, draft-only rules and audit identity semantics are retained. Placard draft/source binding remains its accepted policy; this change does not add a published-only source requirement. Notice, Pricing, Adapter, placard publication fencing, renderer, signatures and download policy retain their existing implementations.
