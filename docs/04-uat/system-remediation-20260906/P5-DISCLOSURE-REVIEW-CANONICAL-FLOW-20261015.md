## Production behavior

New endpoints are `GET /api/regulatory-registry/disclosure-reviews`, `GET .../:subjectType/:subjectId`, and `POST .../:subjectType/:subjectId`. POST requires the existing write scope and carries `idempotency-key`, expectedVersion, sourceSubmissionId, action and reason. Client-supplied actor/verified fields are not accepted as authority. The original platform-admin client factory and BFF path mapping are retained: `/api/...` is transported through the existing `/control-plane-proxy/...` route to the same API resource. The existing identity-session-only CSRF contract is unchanged; no generic policy or issuer change is introduced.

Database-enabled reads use current canonical rows and audit history instead of replacing whole Registry cache state. Decisions use the existing `withTransaction` and `persistChangesWithExecutor`, plus `AuditLogRepository.append` on that same executor. Only this subject's acknowledged profile/credential delta is published; existing C073/peer state is preserved. A pending or failed persistence does not become an approved UI state. An exact retry keeps the complete command identity; changing source/version/action/reason changes its intent. A refreshed service reads durable receipt history rather than relying on a process-only replay map.

NoDB uses the existing Registry data and a per-subject command sequence, retains legitimate synchronous Registry callers, prevents duplicate concurrent decisions on one version, and leaves different subjects independent. Its history is intentionally in-memory, not claimed restart durable. Enabled storage exceptions remain explicit failures, not a switch to noDB/sample data.

Required fields are never filled with placeholders to approve. Central minimum permits null vehicle colour; the existing canonical profile-specific missing-field codes retain a configured colour requirement (including the original Taipei profile). The implementation does not infer a new city/colour rule or force colour globally. This follows `source_specs/01_system_development_team_spec_20260720.md` in the existing Phase1 P5 source bundle. Driver registration is masked in current, historical and response snapshots, while canonical record storage handling is unchanged. Approval cannot clear a suspension/revocation; return does not silently remove an existing blocked/expired credential state.
