## 正式依據與修正邊界

- `app/bookings/page.tsx`、`app/bookings/[bookingId]/page.tsx` 是實際 mounted callers。兩者改呼叫本 task 的 `lib/bank-bookings-data.ts::loadBankBookingsData`，避免改動其他 writer 持有的共用 `bank-dev-read-models.ts`。
- `lib/bank-user-identity.ts::getBankUserIdentity` 是既有 canonical session/tenant/actor/scopes 來源，內部使用 `verifyTenantSession`。新 reader 先取得此身份，再要求既有 `tenant:read`。展示銀行與 persona 僅留在 branding／導覽，不輸入資料 reader；未新增角色、登入、IAM 或 catalog 授權。
- `packages/tenant-auth/src/api-fetch.ts::tenantAuthFetch` 保留使用者 `Authorization: Bearer`、獨立 Cloud Run infrastructure proof、no-store、timeout。新 reader 的 `x-tenant-id` 只來自 verified identity，不採展示銀行、actor headers 或自行鑄造權限。
- 正式 producer：`TenantPartnerController::listTenantOrders` 使用 `toApiSuccessEnvelope(toApiListData(...))`；`TenantPartnerService::listTenantOrders/listTenantScopedOrders/filterTenantOrders` 回傳完整 tenant-scoped `business_dispatch` 清單，支援 `serviceProduct=credit_card_airport_transfer`，此路徑沒有後端分頁截斷。`auth.policy.ts` 的 tenant GET 要求 `tenant:read`。
- `OwnedOrderRecord`、`OWNED_ORDER_STATUSES`、`TenantBookingApprovalState` 與 `SnakeCaseInterceptor` 是型別及 wire 依據。reader 重用純 `normalizeBankUserKeys`，在本地 boundary 將 envelope/nested snake_case 解碼一次，驗證實際使用的投影欄位、日期、tenant、產品、合法 status/approval/direction、重複 IDs 與 programs，再建 list/detail 同源資料。非必要的原始乘客／金額欄位不返回頁面。
- 舊 `mapBookingListItem` 的政策為 `maskedAddress ?? address`。新 reader 正確解碼正式 `masked_address` 並優先使用；缺少 mask 時保留合法 owning address fallback，沒有新增 owning CRUD 地址禁令。乘客電話／姓名、權益／授權 reference 仍遮罩，Ops link 仍 forbidden。既有三角色金額、JSON scope、CSV 規則及 statement/contract 日期修復未修改。
- 正式 ID、program code/label 不再經 `tenantDisplayText` 的展示銀行替換；否則例如 `bank=contoso` 會把來源 `ord_acme_original` 顯示成 `ord_contoso_original`。品牌色及展示標頭仍沿用既有 UI。
- `lib/bookings.ts::paginateBookingItems` 在同一份授權、已篩選資料上切頁，保留 producer 順序與 canonical IDs，不截斷總資料。10/25/50（預設 25）沿用 `apps/tenant-console-web/lib/booking-list.ts` 的既有 UI sizes，僅為呈現選項，未引入業務筆數上限。非法頁碼回第一頁，越界夾到末頁，空資料邊界為 0–0／0。狀態 tabs 保留其他 filters 且跨所有頁計數；篩選／換 tab 重置頁碼；頁碼、詳情連結與返回保留 program/direction/state/period/cardholder/pageSize。
- 非 ready 詳情顯示 alert；只有成功取得權威清單且找不到 canonical ID 才 `notFound()`。空資料不補 seed；denial/outage/malformed 都不冒充正式空資料或 404，不將上游 private error body 顯示給使用者。
