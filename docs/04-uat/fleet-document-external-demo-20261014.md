## Operable demonstration

Open Fleet navigation → **文件示範 · SIMULATION / Document demo · SIMULATION** (`/demo`). Choose fixed example vehicle-registration PDF or supporting-document PNG metadata; no actual file is requested or read.

1. Start simulated storage, choose failure, retry, then choose simulated success or explicitly skip external storage.
2. With simulated storage success, start simulated scanning, choose failure/retry and simulated pass or skip. With skipped storage, explicitly skip scanning; a simulated scan cannot start without simulated stored content.
3. Confirm the example only after both external steps are resolved or skipped. Submit for review, withdraw and resubmit the local sample; the UI uses the existing supply terminology.
4. Download `fleet-document-SIMULATION.json` with the selected example metadata, statuses, attempt counts and ordered timestamped action history. Reset clears the selection, both steps, confirmation, submission and history; subsequent export contains `exampleMetadata: null`.

Pending states wait for the user to select an outcome. There are no network requests or automatic successful outcomes. A simulated scan pass is `simulated_pass`, never a real `scan_state=clean`; skipping is `skipped` through confirmation, submission, withdrawal, resubmission, remount and export.

Only the independent `fleet-document-SIMULATION-v1` browser-local key is read/written. Retry retains selected metadata. Changing the example before confirmation resets its external stages; confirmation locks the selection until reset. Remount replays the actual recorded demo actions. Browser-storage failure visibly reports lost persistence while controls continue in memory. Export failure has a retryable alert. The plain link to `/supply/submissions` carries no demo state, query or production IDs. The portal's authentication, real forms and real API callers are unchanged.
