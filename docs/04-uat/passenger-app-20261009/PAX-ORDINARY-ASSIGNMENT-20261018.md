# 一般調度同單指派與改派

一般調度詳情原本只提供候選第一名的指派按鈕，請求缺少後端既有要求的冪等識別碼；已有待接任務時也沒有一般改派入口。乘客、調度與司機雖有共同 orderId，操作者仍需回審查入口才能繼續。

本次讓一般詳情選擇實際候選，經原 SDK、BFF 和既有 assign/reassign API 指派或改派，沿用原請求確認及重試契約。改派提供既有原因與選填備註；待接任務顯示改派，行程開始及終態不提供該操作。確認成功後重新讀取伺服器狀態，顯示同一原始訂單識別碼、目前司機與任務。

原 A 情境的階段順序保持不變：普通乘客登入及建單、一般調度建立派遣，在一般詳情先指派 B，再於乘客離線時改派 A，司機接單、抵達、上車、完程，最後付款與評價。新增兩張操作原圖與兩份同單任務讀回；驗證被替代任務取消、同一派遣只剩一個待接任務。其他原情境繼續保留。

本地單元只替代上游 HTTP 回應，實際執行控制項、SDK 與 BFF，涵蓋中英文、所選候選與原因、409 修正、未知回應重送及等待中重複點擊。完整瀏覽器與資料庫旅程於既有託管 CI 執行，不在此 VM 啟動產品或瀏覽器伺服器。

這項修補完成的是人工調度操作；乘客建單觸發自動派車、Android／iOS 真機及正式營運仍須另外完成。外部 SMS、車司資格、GPS 與 PSP 保留原本明示的演練模擬，內部訂單、派遣、任務、完程與付款紀錄使用原後端。
