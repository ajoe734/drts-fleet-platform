# 一般客訴工作區的真實活動歷程

客訴列表選案後把 SDK 時間軸方法存成獨立函式再呼叫，遺失實例上下文；歷程請求尚未送出就失敗，連同匯出摘要一起無法顯示。這是內部功能缺陷。改為由原 SDK 實例直接呼叫，活動型別使用既有合約，不添加 API 沒有提供的 actor 欄位。

四項單元案例執行實際頁面的選案 effect 與真 SDK，驗證有紀錄、空紀錄、上游失敗、切案後遲到回應；原程式四項失敗。這些是頁面 effect 的單元界線，不當成整頁瀏覽器通過。

同案操作／15秒列表輪詢只更新列表紀錄，原時間軸 effect 卻只依賴案號；新增備註後案號不變，歷程與匯出摘要便停在舊資料。現在依選中紀錄的新快照重新讀取，沿既有清理函式擋掉舊回應。另兩項真 React effect／SDK 單元案例先重現兩項失敗，再驗證同案重新讀回及舊回應不能覆蓋新歷程。

原三角色同單腳本另外開啟一般 `/complaints?caseNo=…` 工作區，驗證這筆真遺失物案件的時間軸 HTTP、內容、訂單連結及實際畫面。原48階段、斷言與 timeout 保留；客服實際指派、調查、返還與結案仍須各自驗收。沒有改產品權限、驗證或外部供應商設定，也沒有在工作 VM 啟動產品或瀏覽器服務。

同一工作區另經既有表單新增演練處理備註，驗證真API變為處理中、只有建立／新增備註兩筆真歷程，且不重整頁面就能顯示新備註。這只證內部備註與畫面更新，不表示已真人聯繫、完成調查、返還物品或結案。
