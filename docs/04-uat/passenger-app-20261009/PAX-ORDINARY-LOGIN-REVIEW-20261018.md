# 普通乘客登入接上共享演練

一般 `/login` 原本會把簡訊送進演練收件匣，但畫面無法取得驗證碼；首次登入也會因未配置正式條款而停在同意頁。

共享演練已啟用時，普通手機登入使用既有 `review-demo/otp` 收件結果，明示顯示模擬簡訊，再由原 OTP 輸入及驗證流程完成登入。首次同意頁使用既有 `/review/terms`，保存 `review-terms-v1` 與 `review-privacy-v1`。本機 demo 與正式環境沿原流程。

原三角色 48 步旅程保留原有建單、派遣、搭乘、付款、評價與案件斷言，登入改由普通 `/login` 操作。已同意當版條款的回訪帳戶讀回既有同意紀錄；新帳戶必須經原勾選與保存流程。畫面證據僅收登入前及完成後，不收錄驗證碼或 challenge。

本機元件測試在修正前重現兩個卡點；修正後，兩個案例及既有登入、條款、演練測試共 126 項通過。它們使用原 SDK、BFF、OTP／帳戶控制器與服務；測試持久層及 HTTP 邊界在記憶體中。真正瀏覽器與 PostgreSQL 的完整旅程仍由 GitHub 執行，不能由這些元件結果代替。

外部 SMS 與條款使用明示演練內容，不代表真人收訊、正式服務契約、真機驗收或 production 已完成。
