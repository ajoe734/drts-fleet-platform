## 1. 實作範圍與對應規格

### 1.1 金流商 Adapter (`apps/api/src/modules/passenger-app/payment/`)

- **`ecpay-cipher.ts`**：
  - 實作綠界站內付 2.0 專用加解密演算法：`JSON.stringify` → `encodeURIComponent` → `AES-128-CBC`（PKCS7 padding，16-byte ASCII `HashKey` / `HashIV`）→ Base64；解密反之並將 `+` 正規化為 `%20` 後 `decodeURIComponent`。
  - `verifyAndUnwrapEcpayEnvelope` 支援 JSON 物件、JSON 字串以及 `ReturnURL` / `OrderResultURL` 的 `application/x-www-form-urlencoded` `ResultData=<JSON>` 表單格式，驗證外層 `MerchantID`、`RpHeader.Timestamp` / `RqHeader.Timestamp`（10 分鐘時間窗）與 `Data` 密文完整性，遭竄改或過期一律拒絕。
  - `deriveEcpayMerchantMemberId` 由經過驗證的 `drtsPassengerId` 與 `MerchantID` 雜湊產生不可逆之特店會員編號（`mbr_<32-hex>`），並明確阻擋手機號碼、Email 或 `pax:bind:*` 冪等鍵作為輸入。
- **`ecpay-payment-provider.ts` (`EcpayPaymentProvider`)**：
  - **取得綁卡驗證 Token (`createBindingSession`)**：呼叫 `/Merchant/GetTokenbyBindingCard`（Stage: `https://ecpg-stage.ecpay.com.tw` / Prod: `https://ecpg.ecpay.com.tw`），強制要求已驗證之 `ConsumerInfo.Email` 或 `ConsumerInfo.Phone`，將 `OrderResultURL` 置於 `Data` 頂層（預設指向 BFF `/api/passenger-app/payment-methods/ecpay/order-result`），支援設定 `PSP_BINDING_AUTH_AMOUNT_TWD` 驗證刷卡金額，並在綁卡完成且 `TotalAmount > 0` 時透過 `/1.0.0/Credit/DoAction` (`Action: "N"`) 取消驗證授權（正式環境 `sandbox === false` 要求 `DoAction` 回傳確認成功否則拒絕完成綁卡；Stage 測試環境 `sandbox === true` 因綠界官方不提供 `/1.0.0/Credit/DoAction`，於 `BindCardID` 核發後不因 Stage 缺少 `DoAction` 而阻斷綁卡）。
  - **建立信用卡綁定 (`bind`) 與解除綁定 (`unbind`)**：
    - `bind()` 強制要求已驗證之 `context.passengerId`（禁止以 `idempotencyKey` 偽造會員代號），呼叫 `/Merchant/CreateBindCard`，以一次性 `BindCardPayToken` 交換長期 `BindCardID`；支援綠界官方頂層 `Data.BindCardID` 與 `CardInfo.CardValidYY` / `CardInfo.CardValidMM` 欄位（當到期日缺漏或格式錯誤時明確拒絕，絕不偽造 `12/2099`）；若綠界回傳 `ThreeDInfo.ThreeDURL` 則回傳 `action_required` 導向 3DS 驗證。
    - `unbind()` 呼叫 `/Merchant/DeleteMemberBindCard`（`https://developers.ecpay.com.tw/35608/`），傳入 `{ PlatformID: "", MerchantID, BindCardID }` 解除綠界端會員綁卡並清除快取；`PaymentMethodService.remove` 先透過 `PaymentMethodRepository.findRemovableToken` 確認卡片存在且無未結清行程，解密 `tokenEnvelope` 呼叫 `provider.unbind()` 成功後才軟刪除本地 `passenger.psp_tokens`（若綠界解綁失敗則拋出 `503 payment_unavailable` 並保留本地紀錄），確保移除第 5 張卡後綠界與本地同步釋出額度。
  - **回呼通知驗證與 3DS 完成歸戶 (`verifyNotification`, `PaymentMethodService.verifyNotification`, `PaymentMethodRepository.findBindingByMerchantMember`, `PaymentMethodController`)**：
    - `POST /v1/passenger/payment-methods/ecpay/callback`（綠界 `ReturnURL` 幕後回呼）不要求乘客瀏覽器 session cookie，直接透過加密信封驗簽與 `findBindingByMerchantMember` 跨實例對映原發起綁卡之乘客，將 `BindCardID` 以 `PaymentTokenCipher.encrypt` 寫入 `completeBinding`，並回傳純文字 `1|OK`（`text/plain; charset=utf-8`）。
    - `POST /v1/passenger/payment-methods/ecpay/order-result`（綠界 `OrderResultURL` 3DS 瀏覽器跳轉回呼）驗證 `ResultData` 並冪等完成綁卡後，由 BFF 以 `303 See Other` 導回 `/account/payment-methods?ecpay_3ds=completed|failed|unknown`。
  - **行程完成幕後扣款 (`capture` / `readCapture`)**：
    - `PaymentChargeService.execute` 將 `claim.passengerId` 傳入 `EcpayPaymentProvider.capture`，呼叫 `/Merchant/CreatePaymentWithCardID` 時帶入與綁卡一致之 `ConsumerInfo: { MerchantMemberID }`、固定 `Need3D: 0`、新台幣整數金額（`1 .. 200,000` 元）與 `>= 30 秒` HTTP timeout（預設 `35,000 ms`）。
    - 遵守綠界規範：**同一 `BindCardID` 一旦授權失敗即記錄於 `declinedBindCardIds`，禁止對該 `BindCardID` 再次自動重試授權**。
    - 逾時或未收到明確回應時回傳 `unknown`，透過 `/1.0.0/Cashier/QueryTrade` (`readCapture`) 查詢原始交易狀態。
  - **信用卡退款／取消授權 (`refund` / `readRefund`)**：
    - `refund()` 先呼叫 `/1.0.0/CreditDetail/QueryTrade`（綠界查詢信用卡單筆明細 API `35662`）並由 `parseCreditLifecycle` 解析 `RtnValue.Status` 與 `CloseData`：若關帳狀態為已關帳（`CLOSED`）則對 `/1.0.0/Credit/DoAction` 執行 `Action: "R"`（退刷）；若為未關帳（`UNCLOSED`）則執行 `Action: "N"`（取消授權）；若為要關帳（`CLOSING`）則先執行 `Action: "E"`（放棄關帳）再執行 `Action: "N"`（取消授權）；若 `CreditDetail/QueryTrade` 未回傳明確關帳狀態，一律 fail-closed 回傳 `{ status: "unknown" }`，絕不盲送 `Action: "R"`。
    - `readRefund()` 於本地快取不存在（跨實例或 ACK 遺失）時，以原扣款 `idempotencyKey` 推導之 `MerchantTradeNo` 呼叫 `/1.0.0/CreditDetail/QueryTrade` 解析 `parseCreditLifecycle`（檢查退刷／取消授權狀態與 `refundedAmountTwd >= requestedAmountTwd`），確認是否已完成退刷／取消授權，避免重送金流請求。
- **All-or-Nothing Secret 掛載與防呆 (`payment-runtime.config.ts`, `payment-capture.config.ts`, `.github/workflows/deploy-dev.yml`)**：
  - `PSP_PROVIDER=ecpay` 要求 `PSP_MERCHANT_ID`、`PSP_HASH_KEY`、`PSP_HASH_IV`、`PSP_SANDBOX`、`PSP_TOKEN_ENCRYPTION_KEY_NAME` 五個環境變數全有或全無；任一缺漏即退回 `UnconfiguredPaymentProvider` (`available: false`)。
  - 當 `provider.name === "ecpay"` 時，`paymentCapturePolicyFromEnv` 強制禁止 `retryDefinitiveDeclines: true`。

### 1.2 前端 Hosted Fields 元件、BFF 路由與每會員 5 張卡上限 (`apps/passenger-app-web/`)

- **`components/payment/ecpay-hosted-fields.tsx` (`EcpayHostedFields`, `createEcpayHostedFieldsPort`, `ECPAY_HOSTED_FIELDS_CSP`)**：
  - 使用 `@drts/ui-tokens` (`P5` token) 渲染 `<div id="ECPayPayment" data-testid="ecpay-hosted-fields-container" />`，自動載入綠界規定之 jQuery 3.5.1 前置腳本與 WEB JS SDK (`sdk-1.0.0.js`)，並以 `ECPay.Language?.zhTW ?? "zh-TW"` 呼叫 `addBindingCard`。
  - 我方 DOM 內不含任何卡號、到期日或安全碼 `<input>` 欄位；`collectCredential()` 接受綠界官方 `PaymentInfo` 契約 `{ BindCardPayToken, MerchantTradeNo }`（不強制要求非契約之 `RtnCode: 1`），並阻擋純數字 PAN 字串。
  - 匯出 `ECPAY_SCRIPT_ORIGINS`、`ECPAY_CONNECT_ORIGINS` 與 `ECPAY_HOSTED_FIELDS_CSP` 常數，提供 BFF 與頁面 CSP 白名單共用。
- **`app/api/passenger-app/[...path]/route.ts`（Passenger BFF 路由）**：
  - 開放 `POST payment-methods/binding-session`、`POST payment-methods/3ds-complete`（需同源 CSRF 與 `pax_session` cookie）、`POST payment-methods/ecpay/callback`（綠界伺服器幕後回呼，驗證加密信封並回傳純文字 `1|OK`）與 `POST payment-methods/ecpay/order-result`（綠界 3DS 跨站表單 POST，驗證 `ResultData` 後依 `data.status` 以 `303 See Other` 導回 `/account/payment-methods?ecpay_3ds=completed|failed|unknown`）。
  - `withSecurityHeaders` 設定 `PASSENGER_PAYMENT_CSP`，允許 `https://code.jquery.com`、`https://ecpg-stage.ecpay.com.tw`、`https://ecpg.ecpay.com.tw`、`https://payment-stage.ecpay.com.tw`、`https://payment.ecpay.com.tw` 之 `script-src`、`connect-src`、`style-src`、`img-src`、`frame-src` 與 `form-action`（頁面路由 `/account/payment-methods` 之 `apps/passenger-app-web/next.config.ts` CSP 正透過 Supervisor 進行 `write_scopes` 協調）。
- **`lib/payment/runtime-fields.ts` 與 `app/account/payment-methods/page.tsx`**：
  - 新增 `isEcpayHostedFieldsRuntime` 與 `paymentFieldsForRuntime` 的預設綠界執行期分支，保留既有 `reviewDemo` / `synthetic` 與 `isDemoMode()` 路徑。
  - `PaymentMethodsPage` 於非 demo、非 review 且未指定 `synthetic`/`disabled` 時掛載 `<EcpayHostedFields onReady={setFields} />`，執行期向後端 `GET /api/passenger-app/payment-methods?binding_session=1` 取得綁卡 session 並傳入 `PaymentMethodsScreen` 的 `hostedFieldsView` 與 `approvedActionOrigins`。
- **每會員最多綁定 5 張信用卡與同步解綁 (`payment-methods-screen.tsx`, `payment-method.service.ts`, `payment-method.repository.ts`, `ecpay-payment-provider.ts`)**：
  - 配合綠界「綁定特店會員」模式每會員最多 5 張卡限制：當已綁定達 5 張卡時，`PM-01` 與 `PM-02` 顯示提示訊息（「每個會員最多可綁定 5 張信用卡。如需新增第 6 張卡片，請先移除既有卡片。」）並停用新增／綁定按鈕；後端 `PaymentMethodService` 與 `PaymentMethodRepository.completeBinding` 亦同步以 `409 card_limit_exceeded` 阻擋第 6 張卡，且移除卡片時呼叫 `/Merchant/DeleteMemberBindCard` 同步釋出綠界端綁卡額度。

## 3. Sandbox 實機驗收狀態 (`pax-psp_adapter_sandbox_verified`)

- **目前狀態**：待外部綠界 Stage 實機驗收（`drts-dev-devcc-20260825` 專案中 5 個 `drts-dev-psp-*` secret 最新版本 metadata 已為 `ENABLED`，但目前 `DEV_PAX_REVIEW_DEMO_ENABLED=true` 依審查模式設計固定注入 `PSP_PROVIDER=fake`，且本機／VM 受規則限制不直接啟動開發伺服器或讀取雲端 secret 值）。
- **綠界官方 Stage 環境對 `Credit/DoAction` 之限制（依綠界官方文件 `35642` 與 v4 Task Spec）**：
  - 依綠界站內付 2.0 官方技術文件（`https://developers.ecpay.com.tw/35642/`），由於測試環境（Stage）並未真正向收單銀行進行授權與關帳，**整個信用卡關帳／退刷／取消授權 API（`/1.0.0/Credit/DoAction`）在 Stage 測試環境均不提供服務**。
  - 因此，`EcpayPaymentProvider.refund()`、`readRefund()` 與 `cancelBindingAuthorization()` 對 `/1.0.0/CreditDetail/QueryTrade`（`35662`）及 `/1.0.0/Credit/DoAction`（`R`、`N`、`E`→`N`）之完整狀態機已由單元契約測試驗證，而實機 `Credit/DoAction` 呼叫依 v4 task spec 條件式保留至正式特店環境（Production）驗證，不在 Stage 偽造退刷成功紀錄。
- **後續實機驗收步驟**：
  1. 於目標測試環境將 `DEV_PAX_REVIEW_DEMO_ENABLED` 切換為 `false`（或於獨立 Stage 驗收目標啟用 `PSP_PROVIDER=ecpay`）並透過 `deploy-dev.yml` 部署。
  2. 於綠界 Stage Sandbox 執行 WEB JS SDK 綁卡（`GetTokenbyBindingCard` → `getBindCardPayToken` → `CreateBindCard` → 3DS `OrderResultURL` / `ReturnURL`）與行程完成幕後扣款（`CreatePaymentWithCardID` + `Cashier/QueryTrade`），將遮罩後之實機回應證據保存於 `.local/passenger-app-20261009/psp-ecpay/`。
