# 同一訂單的客服內部處理流程

Task-ID: OPS-COMPLAINT-LIFECYCLE-20261016

乘客、調度與司機完成同一筆真實後端訂單後，乘客以原表單建立遺失物案件。
既有案例已驗建立、一般客服列表讀取及新增備註；本次沿相同案件補驗指派、
解決與關閉。這些是內部功能，不能以缺乏真人聯絡或外部設備為由略過。

`pax-review-shared-order-demo.spec.ts` 在原 A 案的備註之後，操作原一般客服工作區：

1. 使用既有示範處理人 `AGENT-OPS-002`，經原指派表單及 POST 指派。
2. 選擇原類別允許的 `resolved_other`，以明示虛構的處理說明解決案件。
3. 經原關閉表單關閉案件；逐次讀回同 caseNo、orderId、處理人及實際狀態。
4. 全程不重整或導頁，逐次要求同頁顯示該次真實歷程備註。
5. 核對完整五筆歷程、關閉後無新增備註操作、原訂單連結，以及實際匯出摘要。

原 48 階段、既有斷言、等待、重試政策及逾時維持；新增流程沿既有案例執行。
實際瀏覽器與 PostgreSQL 驗證僅在 GitHub hosted runner 或共享雲端環境執行，
本 VM 不啟動產品、瀏覽器或資料庫服務。

外部處理結果是演練：沒有致電真人、取回物品或聲稱真實失物已返還。
內部案件若實際成功關閉，僅採認該筆演練資料的真 API 與持久化狀態。
