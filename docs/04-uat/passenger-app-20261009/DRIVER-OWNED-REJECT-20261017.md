修補沿既有任務讀模型與狀態：待接受自營任務提供婉拒按鈕，確認畫面可保留任務或填選填原因。確認後呼叫原 SDK，送既有 `driver_rejected` 原因碼及去空白的選填說明；只在後端成功後關閉並重新讀取任務。失敗保留明確錯誤與重試，原接受／完成與轉派單行為保持。沒有更動身份、資格、派車、保留資源、權限或外部平台政策。

本機驗證只替換原生、定位、裝置儲存、router 與 HTTP 邊界，真正執行行程元件、Canvas、Driver app client 與共用 SDK；不啟動伺服器、不建立本機資料庫。案例涵蓋 Web／原生元件路徑、選填原因省略、舊讀模型相容、保留任務、失敗再送、送出中防重入、已接單及轉派單／原讀模型不允許時的原行為。這些不是實體 Android／iOS 或 PostgreSQL 證據。
