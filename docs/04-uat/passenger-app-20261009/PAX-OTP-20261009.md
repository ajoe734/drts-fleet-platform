## 正式呼叫路徑與安全邊界

- `PassengerOtpController`：`POST auth/otp/request`、`POST auth/otp/verify`、`GET auth/providers`，均有真實 `OpenRoute` metadata。既有 `BootstrapAuthGuard.activatePassenger` 驗證 BFF metadata／乘客 Bearer；OTP service 依用途再次驗證持久化帳號與 session。
- `PassengerOtpService.request`：canonical target → 已登入用途綁定 → provider availability → PG target/IP advisory locks → DB clock → rolling quota／cooldown → 撤銷舊 challenge／存新雜湊 → delivery。request 不查帳號是否存在。
- code 是 `randomInt(1_000_000)` 補足六位，challenge 是 32-byte 隨機 bearer。目標／IP／challenge／code 使用 domain-separated HMAC-SHA256 與 runtime pepper。code digest 包含 challenge、target、provider、purpose、帳號與 session family。
- PG 只存 digest 與一次性 transaction binding；target、IP、challenge bearer、code 明文不進 OTP 表。六位 code 不進 public response、exception envelope 或 log。
- 同 target 全用途共用 60 秒冷卻、每 rolling hour 5 次；IP 全 target／provider 共用 quota。失敗 delivery 仍計次。重送使前一 challenge 失效。
- `verify` 使用 `FOR UPDATE`，在固定 32-byte digest 上呼叫 `timingSafeEqual`；不存在的 challenge 也比較 dummy digest。錯誤、過期、消耗、五次鎖定、target/provider 不符皆回通用 `invalid_code`。失敗計數先 commit 再拋錯。
- 成功 proof 先持久化單次消耗，再呼叫既有帳號服務；下游失敗也不恢復 proof。login：`findOrCreateByIdentity` → `issueSession`；link：`linkIdentity`；聯絡手機：`verifyContactPhone`。不因相同 email／phone attribute 合併帳號。
- link／verify_contact_phone 綁定 exact 帳號與 refresh family；同 family refresh 可續用，跨帳號／新 family 拒絕。消耗前及帳號寫入時重查 active session，涵蓋 logout／delete／expiry。OTP connection 內不巢狀開 account transaction。
- `NotificationDeliveryService.sendPlatformMail` 是立即寄送：使用 `MailTransport.sendPlatform`、`tenantId: null`，不捏造 tenant，也不把短效 code 留在 tenant outbox。只回傳 bounded status，SMTP acknowledgement／exception 不外露。provider acceptance 不代表人類收件。
- tenant `EnqueueMail`／`TransportMessage`／`MailTransport.send` 的 string tenant 契約保留；新增 optional `sendPlatform`，舊 adapter 仍可 tenant 寄信。Remote SMTP／Mailpit 在相同 serializer/send path 增加平台入口。Remote SMTP 的既有一參數 constructor 保留；新增可選 factory 供外部 SMTP 邊界注入測試，正式 env factory 使用原本預設 nodemailer。所有 constructor callers 已搜尋核對。
- `UnconfiguredSmsPort` 不因 SMS env 存在而假稱可用；預設 providers 只有設定完整的 email，phone request 回 `503 not_configured`／「未設定驗證碼服務」。SMS adapter 由 PAX-SMS-PROVIDER 替換 `SMS_PORT`。

## Runtime 設定與跨 task 接點

| 設定                                                     | 行為                                                                                                                                                  |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PASSENGER_OTP_PEPPER`                                   | 至少 32 字元的安全隨機 Secret Manager 值；缺少／過短則 OTP provider 關閉，不使用預設 key。worker 未建立／讀取真實 secret。                            |
| `NOTIFICATION_FROM_EMAIL`，備援 `REMOTE_SMTP_FROM_EMAIL` | 平台 sender；沿用現有 SMTP／recipient allowlist 及 outbox factory 設定，不放寬非 production allowlist。                                               |
| `PASSENGER_OTP_IP_HOURLY_LIMIT`                          | 預設 20，允許 1–1000；target quota 固定 5。                                                                                                           |
| `PASSENGER_OTP_TRUSTED_PROXY_HOPS`                       | 預設 0，使用 socket peer，忽略偽造 XFF／body IP；非零須由部署端確認受保護的固定 BFF／proxy 拓樸。依右側 hop 取 IP，IPv6／IPv4-mapped address 正規化。 |

PAX-WEB-DEPLOY 必須提供 pepper 與核對 proxy 拓樸；預設 socket-peer 限流會把同一 BFF peer 的流量合計，不冒稱已取得瀏覽器 IP。PAX-OIDC／FACEBOOK 後續需把各自實際可用的 provider 加入 providers 回傳；本 task 只啟用 email／phone 能力。沒有部署、外部帳號建立、live SMS／OAuth／PSP 請求。
