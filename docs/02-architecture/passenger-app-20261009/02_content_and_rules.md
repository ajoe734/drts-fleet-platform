### E-18 / E-18b 評價規則 (源自 G201011 §3.2 lines 90-103)

- **開放時機**：必須於行程完成**且**付款完成後方可填寫。
- **保留期限**：評價入口於行程完成後保留 24 小時。
- **星等對應**：1 很差／2 不滿意／3 普通／4 滿意／5 非常滿意。
- **回饋標籤**：
  - 正面：車內整潔、駕駛親切、路線順暢、準時到達
  - 待改善：駕駛態度、車內氣味、繞路、遲到、駕駛違規
- **意見框限制**：補充意見最多 200 字。
- **E-18b 規則（低分導流）**：當星等 ≤ 2 時，於意見框下方出現「需要客服與您聯繫嗎？」及開關（預設開）。開啟時，送出後自動建立客訴案件。
- **不可修改與隱私**：評分送出後不可修改。文案註明：「評價送出後即不可修改。您的評價將以匿名方式提供，作為提昇服務品質的依據。」

## 2. 11 項矛盾項目盤點與處置

| 項目                     | 矛盾描述                                                  | 處理方式                                                                                         |
| ------------------------ | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 1. 網域                  | 舊設計/文件寫 `ride.zhixing.tw` 或 `(App Domain Pending)` | **採用值**：`ride.smarttransport.tw`（依據 2026-10-09 使用者決定）                               |
| 2. 客服電話              | 舊設計示例有 `0800-090-000` 等                            | **採用值**：`02-2944-0985`（依據 G201011 及 common.md）                                          |
| 3. 費率頁文號            | 舊設計有虛構文號「北市交運字第1130042號」                 | **採用值**：一律改寫為「依臺北市政府公告計程車運價」，不虛構文號（依據 G201011）                 |
| 4. 取消費                | G201011 寫「指派前取消不收費」，但派車後的取消費用不明確  | **待使用者確認**：派車後（指派後）取消是否收費？取消後的 dispatch 政策為何？（保持 explicitly pending）|
| 5. 評價導流標準          | 其他系統可能有不同低分標準                                | **採用值**：嚴格依照 G201011，≤ 2 星顯示客服聯繫並於開啟時建立客訴                               |
| 6. 即時與預約            | 畫面上可能有即時叫車選項，但系統不支援                    | **採用值**：僅提供預約叫車，頁尾標示「本服務僅提供預約叫車」（依據 common.md）                   |
| 7. E-04 欄位缺漏         | 現有系統/收據中缺少遮罩執登號、支付方式等                 | **採用值**：補齊 G201011 規定的 13 個欄位                                                        |
| 8. 登入方式              | 舊決策仰賴夥伴 B2B2C 登入                                 | **採用值**：手機、Email、Google、FB、LINE 登入（依據 2026-10-09 使用者決定）                     |
| 9. 金流與付款            | 舊決策中對 C 端乘客金流未定案                             | **採用值**：線上刷卡（依據 2026-10-09 使用者決定）                                               |
| 10. 第一方 App 優先度    | 舊決策不做第一方 App                                      | **採用值**：Phase A 優先做手機網頁 App，Phase B 再做 Expo 原生 App（依據 2026-10-09 使用者決定） |
| 11. Apple 登入 (Phase B) | 根據 App Store 規則 4.8，有第三方登入必須提供 Apple 登入  | **待使用者確認**：送審前需確認是否實作 Apple 登入                                                |
