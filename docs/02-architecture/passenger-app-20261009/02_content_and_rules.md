### E-18 / E-18b 評價規則 (源自 G201011 §3.2 lines 90-103)

- **開放時機**：必須於行程完成**且**付款完成後方可填寫。
- **保留期限**：評價入口於行程完成後保留 24 小時。
- **星等對應**：1 很差／2 不滿意／3 普通／4 滿意／5 非常滿意。
- **回饋標籤**：
  - 正面：車內整潔、駕駛親切、路線順暢、準時到達
  - 待改善：駕駛態度、車內氣味、繞路、遲到、駕駛違規
- **意見框限制**：補充意見最多 200 字。
- **E-18b 規則（低分導流）**：當星等 ≤ 2 時，於意見框下方出現「需要客服與您聯繫嗎？」及開關（預設開）。開啟時，送出後自動建立客訴案件。
- **不可修改與隱私**：評分送出後不可修改。文案註明：「評分送出後不可修改；評分以匿名方式提供駕駛，並用於駕駛服務品質管理」

### E-19a 與 E-19b 確認文案 (G201011 v1.0)

- **E-19a 首次使用宣告 (First-use acknowledgement)**：
  依據 G201011 §3.3 line132 規定：首次叫車前必須強制展開閱讀一次 (first-time users must open it once before first order)。必須呈現 eight-row disclosure (八項費用說明)，以及下方按鈕「我已閱讀並同意」，並附上 footer：「下單前將再次顯示費用摘要供您確認」。
- **E-19b 叫車前確認勾選框 (Checkbox/confirmation)**：
  依據 G201011 §3.3 line150 規定，必須呈現標題「費用規則」、連結「查看完整費用與優惠說明」，並精確包含以下四行費用摘要：
  「車資依核定運價計費（含延滯計時）」
  「預約費、取消費（指派前）、等待費：不另收」
  「國道通行費經您同意行駛後實收」
  「車內汙損清潔費實支實付」
  並附帶 checkbox：「我已確認費用與優惠說明」；未勾選前 disabled confirm 按鈕。下方註明：「系統將記錄您的確認時間，作為爭議處理依據」。

### 費率頁數字 (E-05 公開計費說明，2026-10-10 定案)

採用 2026-10-10 使用者定案（canonical machine root 的
`.local/passenger-app-20261009/common.md` 補充 A7）與
[臺北市公共運輸處公告說明](https://pto.gov.taipei/News_Content.aspx?n=6B4D38874E971F4B&s=63C0CCF302898D25)。
自民國 112/04/01 零時（`2023-04-01T00:00:00+08:00`）起實施：

- 起程運價 (1.25 公里): NT$ 85
- 續程運價 (每 200 公尺): NT$ 5
- 延滯計時（車速每小時 5 公里以下累計每 60 秒）: NT$ 5
- 夜間加成 (23:00–06:00): 每趟固定加收 NT$ 20；跨時段以上車時間為準。

**作廢追溯**：前版從 `E05_公開計費說明.png` 提取的「每 80 秒 NT$5、夜間
+20%」由上述使用者決定取代，保留來源 ZIP hash 供追溯，不能再用於 seed 或公開費率。
正式版本 ID 為 `taipei-20230401`（系統識別碼，非公告文號）。

計費跳數依[汽車運輸業管理規則第 91 條附件二「計程車計費表功能規範」
二(三)](https://laws.gov.taipei/Law/File/0000199457)（PDF 印頁 6–7）：
距離不超過起程時續程跳數為 0，超過時 `(距離−1250)/200` 無條件進位；
延滯跳數為累計延滯秒數 `/60` 無條件捨去。夜間僅提高起程金額至 105 元，
續程及延滯金額不變。本版本所有金額均為 5 元倍數，合計不再加價進位
（資料庫 `total_increment=5, total_rounding=floor`，對本版本金額為恆等操作）。
無機場或春節比例加成，因此不套用附件中的比例換算。

試算的低速延滯時間仍不可由 geo 總時長推斷；区間明示採零至全程時長，
按上述跳數計算。未知通行費、清潔費與專程送還車資不預加。
春節加價有獨立日期公告，本次定案未提供各年度日期，不能將其放入無條件
`additionalFees`；本 seed 為一般日運價，不宣稱覆蓋春節或機場特殊費率。

## 2. 11 項矛盾項目盤點與處置

| 項目                     | 矛盾描述                                                  | 處理方式                                                                                                |
| ------------------------ | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 1. 網域                  | 舊設計/文件寫 `ride.zhixing.tw` 或 `(App Domain Pending)` | **採用值**：`ride.smarttransport.tw`（依據 2026-10-09 使用者決定）                                      |
| 2. 客服電話              | 舊設計示例有 `0800-090-000` 等                            | **採用值**：`02-2944-0985`（依據 G201011 及 common.md）                                                 |
| 3. 費率頁文號            | 舊設計有虛構文號「北市交運字第1130042號」                 | **採用值**：一律改寫為「依臺北市政府公告計程車運價」，不虛構文號（依據 G201011）                        |
| 4. 取消費                | G201011 寫「指派前取消不收費」，但派車後的取消費用不明確  | **待使用者確認**：派車後（指派後）取消是否收費？取消後的 dispatch 政策為何？（保持 explicitly pending） |
| 5. 評價導流標準          | 其他系統可能有不同低分標準                                | **採用值**：嚴格依照 G201011，≤ 2 星顯示客服聯繫並於開啟時建立客訴                                      |
| 6. 即時與預約            | 畫面上可能有即時叫車選項，但系統不支援                    | **採用值**：僅提供預約叫車，頁尾標示「本服務僅提供預約叫車」（依據 common.md）                          |
| 7. E-04 欄位缺漏         | 現有系統/收據中缺少遮罩執登號、支付方式等                 | **採用值**：補齊 G201011 規定的 13 個欄位                                                               |
| 8. 登入方式              | 舊決策仰賴夥伴 B2B2C 登入                                 | **採用值**：手機、Email、Google、FB、LINE 登入（依據 2026-10-09 使用者決定）                            |
| 9. 金流與付款            | 舊決策中對 C 端乘客金流未定案                             | **採用值**：線上刷卡（依據 2026-10-09 使用者決定）                                                      |
| 10. 第一方 App 優先度    | 舊決策不做第一方 App                                      | **採用值**：Phase A 優先做手機網頁 App，Phase B 再做 Expo 原生 App（依據 2026-10-09 使用者決定）        |
| 11. Apple 登入 (Phase B) | 根據 App Store 規則 4.8，有第三方登入必須提供 Apple 登入  | **待使用者確認**：送審前需確認是否實作 Apple 登入                                                       |
