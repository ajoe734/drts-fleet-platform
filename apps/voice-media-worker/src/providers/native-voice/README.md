# OpenAI Realtime Native Voice Candidate Adapter — UV-EXEC-026

Source: `docs/02-architecture/phase1-unattended-voice-booking-sd-20260906.md` §14, Task `UV-EXEC-026`.

This directory provides the fair comparison adapter for the single selected native voice candidate: **OpenAI Realtime** (`gpt-4o-realtime-preview-2024-12-17`).

## 1. Single Candidate Selection Record

In accordance with SD §14.1, this implementation selects exactly one minimal comparison adapter rather than implementing all possible providers or orchestration frameworks simultaneously:

- **Selected Candidate**: OpenAI Realtime (`openai_realtime`).
- **Model ID**: `gpt-4o-realtime-preview-2024-12-17`.
- **API Protocol Version**: `v1` (`/v1/realtime` bidirectional WebSocket / WebRTC event protocol).
- **Audio Telephony Format**: G.711u (`g711_ulaw`, 8,000 Hz, single channel, 20ms packet framing), natively matching carrier CTI trunks without intermediate resampling bridges.
- **Official Documentation Citations**:
  - Realtime API Guide: [https://developers.openai.com/api/docs/guides/realtime](https://developers.openai.com/api/docs/guides/realtime)
  - Realtime SIP Telephony Guide: [https://developers.openai.com/api/docs/guides/realtime-sip](https://developers.openai.com/api/docs/guides/realtime-sip)
  - Realtime Metering & Costs: [https://developers.openai.com/api/docs/guides/realtime-costs](https://developers.openai.com/api/docs/guides/realtime-costs)

### Selection Justification vs. Gemini Live
While Gemini Live (`gemini-2.0-flash-exp`) is also listed in SD §14 as an alternative candidate, OpenAI Realtime was selected as the minimal comparison adapter because:
1. It offers native G.711u 8 kHz telephony audio streaming documented explicitly for SIP carrier telephony (`realtime-sip`), avoiding additional multi-stage transcoding latency.
2. It defines strict event-level semantics for `input_audio_buffer.clear`, `response.cancel`, and `conversation.item.truncate` (with precise `audio_end_ms` offset), directly fulfilling SD §9 and §11 requirements for local mute and audio timing fences upon caller barge-in.
3. Its function calling protocol cleanly maps to our `@drts/contracts` JSON schemas without external orchestration frameworks.

## 2. Shared Gate & Transaction Discipline

Per acceptance criterion 2, the candidate model does NOT create a separate order truth or bypass business validations:
- **Shared Tool Gateway**: Model function call requests are converted into `@drts/contracts` `VoiceToolProposal` schemas and forwarded to `VoiceToolGatewayService`.
- **No Direct Mutations**: The model is forbidden from directly issuing database writes or order creation. Booking orders require an explicit `create_booking_receipt` invocation containing a valid, unexpired `confirmation_token` generated by `VoiceConfirmationService` after deterministic readback.
- **Cancellation & Truncation Fencing**: When the caller interrupts the model (`input_audio_buffer.speech_started`), `RealtimeSharedGateBridge` coordinates with `VoiceMediaOutputFence` (synchronously clearing the audio sink and advancing the playback generation) and `VoiceConfirmationController` (invalidating the active readback plan). The adapter emits `conversation.item.truncate` with the exact played audio offset (`sentAudioMs`).
- **In-flight Correction**: Corrections invalidate prior draft values; no stale confirmation can be applied to corrected orders.

## 3. Hermetic Fixture Discipline & Production Guard

Neither OpenAI nor carrier SIP trunks have production credentials configured in this repository (which is explicitly gated at `UV-EXEC-027` and `UV-EXEC-028`):
- `isProductionCapable = false` and `mode = "fixture"` are strictly hardcoded.
- Invoking `connect()` with `production: true` immediately throws `VoiceMediaProviderError("voice_fixture_forbidden")`, preventing unauthorized execution or forged production capabilities.

## 4. Retained Unknowns

The following attributes are explicitly recorded as `unknown_pending_live` in accordance with acceptance criterion 3:
- **Taiwanese Hokkien (`nan-TW`) & Hakka (`hak-TW`) Quality**: While OpenAI documents Mandarin (`zh-TW`), native Taiwanese dialects are not formally benchmarked or SLA-guaranteed by the provider.
- **Carrier PSTN Network Characteristics**: Real-world packet loss, jitter buffer behavior, and carrier SIP trunk renegotiation.
- **Exact Live Telephony Operating Costs**: Real billing records vs. theoretical token formulas.
All of these items are explicitly retained for live telephone evaluation in `UV-EXEC-028`.
