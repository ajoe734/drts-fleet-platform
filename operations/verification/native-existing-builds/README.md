## 2. Read-Only Architecture and Guardrails

1. **Workflow Mode Separation (`.github/workflows/build-driver-ios.yml`)**:
   - `mode: build` (default): Executes the unchanged iOS build and optional TestFlight submission steps.
   - `mode: lookup-existing`:
     - Rejects `submit: true` before execution and gates all build, configuration mutation, API health check, and TestFlight submission steps behind `(inputs.mode || 'build') == 'build'`.
     - Executes `node operations/verification/native-existing-builds/lookup.cjs guard` and `node operations/verification/native-existing-builds/lookup.cjs lookup`.
     - Always uploads `.artifacts/native-existing-builds/driver-existing-builds-receipt.json` (`if: always() && inputs.mode == 'lookup-existing'`).
2. **Controlled EAS CLI `build:view` Lookup (`operations/verification/native-existing-builds/lookup.cjs`)**:
   - Enforces strict UUID validation on `DRIVER_APP_EAS_PROJECT_ID`, `LOOKUP_ANDROID_BUILD_ID`, and `LOOKUP_IOS_BUILD_ID`, and 40-char SHA validation on `LOOKUP_EXPECTED_SOURCE_SHA`.
   - Prepares an ephemeral, read-only EAS project directory in `os.tmpdir()` with `EAS_NO_VCS=1` and `EAS_PROJECT_ROOT=<projectDir>` so `NoVcsClient.getRootPathAsync()` resolves the project root directly without invoking `git rev-parse --show-toplevel` in `/tmp` or dirtying the checked-out git working tree, and strips any pre-`enableJsonOutput()` stdout warning lines in `parseEasBuildViewJsonStdout()` before `JSON.parse`.
   - Invokes `npx --yes eas-cli@21.4.0 build:view <BUILD_ID> --json` and reconciles:
     - EAS project ID (`7f8583f8-a32d-49b8-973d-ddd34ac9b71c`), slug (`drts-driver-app`), owner (`ajoe734`), and app identifier (`com.cctechsupport.drts.driver`)
     - Source commit (`gitCommitHash`) vs expected source SHA (`0e722795dec202e960e504a8fa67526fc567ed0f`) and git ancestry against checked-out `HEAD`
     - Profile (`buildProfile`), distribution (`distribution`), marketing version (`appVersion`), build version (`appBuildVersion`), and terminal status (`FINISHED` / `ERRORED`)
   - If the existing GitHub `EXPO_TOKEN` identity is denied `READ` access (`Entity Not Authorized` / `UNAUTHORIZED_ERROR` / `AUTHENTICATION_REJECTED`) on either `stderr` or early pre-`enableJsonOutput()` `stdout`, `lookup.cjs` inspects both streams in memory (while retaining `stderrSha256` and emitting zero raw error text), records `status: "blocked_unauthorized_awaiting_operator"`, sets `awaitingOperatorAction: true`, performs **zero retries**, does not call `build:view` on remaining IDs (`skipped_after_authorization_denial`), and uses **no alternate identity**.
3. **Self-Contained Cryptographic & Manifest Inspection (`operations/verification/native-existing-builds/inspect-artifacts.py`)**:
   - Uses only Python 3 stdlib (`zipfile`, `plistlib`, `struct`, `hashlib`) and system `openssl` (requiring zero external `pip install` packages at runtime).
   - **Android (`.apk`)**: Verifies APK Signature Scheme v2 (`0x7109871a`) 1 MiB chunk content digests, `signed_data` signature, and leaf X.509 certificate public-key binding; parses binary `AndroidManifest.xml` (`package`, `versionCode`, `versionName`, `uses-sdk`, permissions, activities, services, deep-link schemes) and embedded `assets/app.config` while omitting `<meta-data>` API keys.
   - **iOS (`.ipa`)**: Verifies `embedded.mobileprovision` CMS signature and main 64-bit Mach-O executable (`LC_CODE_SIGNATURE` SuperBlob `0xfade0cc0`) CMS signature, all `CodeDirectory` (`0xfade0c02`) executable page hashes, special slot 1/3/5/7 hashes (`Info.plist`, `CodeResources`, signed entitlements), and provisioning profile certificate/entitlement consistency while never recording device UDIDs (`device_identifiers_recorded: false`).
4. **Zero-URL & Zero-Secret Receipt Invariant (`assertRedactedReceipt`)**:
   - Enforces that the serialized JSON receipt contains neither `EXPO_TOKEN`, nor any `http://` or `https://` URL (including signed GCS redirect URLs, capability artifact URLs, or `logFiles` URLs), nor any private key or device UDID.
